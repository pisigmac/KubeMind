Tricore End-to-End Request Architecture

Detailed visual breakdown of how client prompts are routed, processed, executed, and traced.

01

1. Client Prompt Dispatch

Client SDK / UI → HTTP POST /v1/missions
Client initiates a prompt with header X-Workspace-ID: default targeting the Agents service.
curl -X POST http://localhost:9082/v1/missions -d '{"prompt": "Build test suite", "mode": "sync"}'
02

2. Agents Mission & Task Planner

Agents Engine (:9082)
AgentEngine creates a mission record in PostgreSQL with status running and inspects registered tool schemas.
MissionModel(id="uuid", workspace_id="default", status="running")
03

3. Mind Hybrid Knowledge Retrieval

Mind Engine (:9081)
Invokes the knowledge tool. Mind computes query embeddings using Ollama and queries PostgreSQL via pgvector + BM25 keyword matching.
POST http://mind:8081/v1/query → Top-k search scores (vector: 0.91, keyword: 0.98)
04

4. Router LLM Gateway & Redis Caching

Router Engine (:9080)
Calculates SHA256 key of prompt and checks Redis cache. On cache hit: returns in <10ms. On miss: routes request to local Ollama (llama3.1) with circuit breaker protection.
POST http://router:8080/v1/chat/completions → Provider: Ollama (circuit_state="closed")
05

5. Sandboxed Tool Execution

Agents Execution Engine
Executes planned tool calls (read_file, write_file, shell, code_analyzer) within workspace scope.
FilesystemTool.write_file(path="/tmp/tricore/default/test_output.txt")
06

6. Sentinel Telemetry & Real-Time Broadcast

Sentinel Engine (:9083)
Emits span logs across services to Sentinel. Saves span record to SQLite database and broadcasts live execution events over WebSockets.
WS ws://localhost:9083/v1/stream → broadcast({"type": "span", "service": "agents", "status": "ok"})
